# Systems and Applications Overview

Systems and applications combine assumptions, primitives, proof systems, protocols, and operational controls into user-facing behavior. These pages use a case-study format, but their taxonomy level is `system`.

## Current systems and applications

| System or application | Main design question |
| --- | --- |
| [Private payments](/docs/systems-and-applications/private-payments) | How can value move while limiting transaction linkage and preserving monetary rules? |
| [ZK rollups](/docs/systems-and-applications/zk-rollups) | How do validity proofs compose with data availability, sequencing, and governance? |
| [Secure messaging](/docs/systems-and-applications/secure-messaging) | How do channels, ratchets, devices, backups, and metadata interact? |
| [Identity wallets](/docs/systems-and-applications/identity-wallets) | How do credentials, selective disclosure, issuers, and revocation compose? |
| [Encrypted mempools](/docs/systems-and-applications/encrypted-mempools) | Which ordering and committee assumptions remain after transaction contents are encrypted? |
| [Private machine-learning analytics](/docs/systems-and-applications/private-machine-learning-analytics) | What do secure aggregation, MPC, FHE, and output controls each protect? |
| [Private DAO voting](/docs/systems-and-applications/private-dao-voting) | How do eligibility, ballot secrecy, duplicate-vote prevention, and tallying compose? |
| [Coercion-resistant voting](/docs/systems-and-applications/coercion-resistant-voting) | What additional system properties are needed beyond ballot secrecy? |
| [Anonymous airdrops](/docs/systems-and-applications/anonymous-airdrop) | How can eligibility and one-time claims be enforced without public identity linkage? |
